# 查询可靠性修复

日期：2026-11-02。基线：bc73b45767eb0e28f0f4a5f8ee6d290ffacd81e6。

## 现象与修复

| 问题 | 根因 | 修改 |
| --- | --- | --- |
| 非流式失败仍返回“处理完成” | 执行层捕获异常，接口没有检查任务状态 | 失败返回 HTTP 502 和 failed；空答案记失败 |
| 查询期间阻塞其他请求 | async 接口直接调用同步工作流 | 使用 asyncio.to_thread，增加健康检查并发测试 |
| SSE 多页面缺消息 | 同一任务共用消费队列，断开连接删除队列 | 改为每个订阅者独立游标轮询持久日志 |
| 恢复后读到旧 error 就断开 | 未区分历史终止事件与后续运行 | 存在后续事件或任务处理中时跳过旧终止事件 |
| 恢复生成出现重复的部分答案 | 旧 delta 与重新生成的 delta 拼接 | 生成前发送 ready.reset，final 覆盖最终文本 |
| 已完成检查点恢复成空回答 | 仅从恢复后的增量读取答案 | 先读取检查点已有答案，再接收增量 |
| 并行分支可能相互覆盖 | 每个节点返回完整旧状态 | 节点入口复制状态，仅提交实际变化 |
| 工具 query 参数未执行 | 路由只保存工具名 | 保存每个工具的 query 并传入检索节点 |
| RRF 无法合并同一父块 | BM25 和向量使用不同前缀 | 统一为 parent:父块ID |
| 首篇长文使上下文为空 | 超预算直接 break | 在剩余预算内截取并标记 |

检索反馈决策作为新增功能单独记录在 `docs/standards/query-decisions.md`。测试见 `tests/test_query_reliability.py`，实际运行报告见 `examples/tests.xml`。

## 未验证的运行边界

模型与业务服务使用替身的回归测试验证代码行为。尚未在真实企业部署中执行 kill-process 故障矩阵、长时间负载、多 worker 恢复或图像入库评测。SQLite 轮询 SSE 的资源开销还需按连接数压测。
