# 查询决策设计

## 工作流

查询依次经过设施确认、工具路由、并行检索、RRF、重排、证据检查和答案输出。设施确认用于结合会话历史理解对象；工具路由负责选择检索方式，证据检查负责判断当前结果是否足以继续回答。

工具选择和证据检查分为两个阶段：前者依据问题决定去哪里查，后者依据实际返回内容决定是否还要查。这样可以保留明确的执行骨架，也能处理首次检索为空或用户条件不完整的情况。

## 参数与并行状态

模型生成的 `query` 参数随工具选择一同保存，并传入对应节点。同一轮可以选择多种工具；同一工具出现多组参数时采用最后一组。每轮最多执行五种检索工具。

并行节点只提交自己的状态变化，避免用旧状态覆盖其他分支结果。每轮开始清空检索结果，上一轮的证据摘要保存在 `decision_trace` 中。BM25 与向量检索统一使用父块标识，使相同文档能够在 RRF 中合并。

## 决策与停止条件

| 决策 | 后续行为 |
| --- | --- |
| answer | 将当前检索内容送入答案生成 |
| retry | 使用新的查询重新进入工具路由 |
| clarify | 返回需要用户补充的问题 |
| stop | 返回资料不足状态及原因 |

证据检查采用结构化输出。补查缺少查询词、追问缺少问题或模型调用失败时，任务返回失败。最多执行两轮检索；第二轮仍请求补查时，返回 `incomplete`。轮数上限控制调用规模，总时延还取决于外部接口超时。

任务记录保存工具查询参数、返回摘要、模型建议及简要依据。达到上限时，最终执行结果以 `next_action` 和 `result_status` 为准，不能仅根据模型原始建议判断任务已完成。

## 证据预算与适用范围

证据检查最多读取十段内容，每段最多两千字符。答案生成使用单独的字符预算，超长文档按剩余预算截取并标记。截断能够限制上下文开销，也可能丢失后部条款，因此仍需评测长文档中的证据覆盖。

当前检查依赖模型判断，未实现逐句引用蕴含校验、用户级文档权限过滤和完整的制度冲突规则。检索文档用于追溯来源，不能单独证明答案中每项结论都成立。
