# 查询决策与限制

查询经过设施确认、模型工具路由、并行检索、RRF、重排、模型证据检查、答案输出。证据检查可以返回 `retry`，将改写后的问题送回工具路由；最多两轮，每轮最多选择五种工具，同一工具重复调用时采用最后一组查询参数。

工具调用的 `query` 会传入对应检索节点。每轮开始清空检索结果，旧结果摘要保存在 `decision_trace` 中，避免没有执行的工具结果混入本轮。并行节点只返回自己更新的字段，防止完整旧状态覆盖其他分支结果。

证据检查使用结构化输出，选择回答、补查、追问或停止。非法结构或模型调用失败会使任务失败；达到补查上限返回 `incomplete`。检查结果与证据摘要保存到任务记录中，只记录简要依据，不记录模型内部思维过程。

当前证据检查最多读取十段、每段两千字符，是有截断的模型判断，不能代替原文事实核验。最终回答仍是文本生成，没有逐句引用蕴含校验、权限过滤或完整制度冲突规则。返回的检索文档代表实际检索结果，不保证答案的每一句都被其支持。

总时延仍受各外部服务超时约束；检索轮数上限不等于请求总时长上限。当前不是生产级多用户 Runtime。
